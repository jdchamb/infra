# Hosts Subsystem (`hosts/`)

This directory houses the host-specific definitions for every machine in the fleet. In the Nix architectural pattern, hosts represent the **"Body"**—the physical or virtual machine identity that stitches together reusable modules from `modules/` and user configurations from `home/`.

---

## Host Roster & Directory Layout

```
hosts/
├── darwin/
│   └── 308-225660/             # Primary Work Apple Silicon MacBook (aarch64-darwin)
│       └── default.nix         # macOS defaults, nix-darwin settings, Homebrew casks
├── nixos/
│   ├── 308-222242/             # Production Linux Workstation (x86_64-linux)
│   │   ├── default.nix         # Desktop compositor imports, services, shares
│   │   └── hardware.nix        # Kernel modules, CPU microcode, disk UUIDs
│   ├── 308-225660NixOSVM/      # Apple Silicon UTM / VZ Virtual Machine (aarch64-linux)
│   │   └── default.nix         # VirtIO paravirtualization, SPICE, QEMU agent
│   ├── lab-probook/            # 5-Node HP ProBook Validation Lab (lab-pb01 .. lab-pb05)
│   │   └── default.nix         # Parameterized clamshell lab node definition
│   └── installer/              # Bootable Live ISO Definitions
│       ├── bootstrap-iso.nix   # Headless minimal console installer
│       └── recovery-iso.nix    # Full graphical rescue USB with partitioning tools
└── windows/
    └── wrk-win01/              # Workstation target profiles for Windows 11
        └── configuration.psd1  # PowerShell DSC node configuration data
```

## Machine Taxonomy

1. **`308-225660` (macOS 27+ / Apple Silicon):**
   * Managed via `nix-darwin` and `homebrew`.
   * Houses the native **Apple Virtualization (`linux-builder`)** hypervisor for compiling Linux packages locally on macOS using performance cores and Rosetta 2.
2. **`308-222242` (NixOS / x86_64 Bare Metal):**
   * High-performance Linux workstation running Wayland desktop compositors (Hyprland, Niri, Sway) and CIFS automounts to USD 308 network shares.
3. **`308-225660NixOSVM` (NixOS / aarch64 Virtual Machine):**
   * Local sandbox running on Apple Silicon via Apple's native `Virtualization.framework` or UTM. Uses Disko on `/dev/vda`.

## Runbook: How to Add a New Host to the Fleet

### Step 1: Create the Host Directory
Choose the operating system directory (`hosts/nixos/` or `hosts/darwin/`) and create a folder matching the new machine's hostname:
```bash
mkdir -p hosts/nixos/my-new-node
```

### Step 2: Define `default.nix`
Create `hosts/nixos/my-new-node/default.nix` (or `hardware.nix` if generated by `nixos-generate-config`):
```nix
{ config, pkgs, inputs, ... }:

{
  imports = [
    ./hardware.nix
    ../../../modules/common/fonts.nix
    ../../../modules/shared/git.nix
    ../../../modules/shared/vim.nix
    ../../../modules/nixos/core/system.nix
    ../../../modules/nixos/core/boot.nix
    ../../../modules/nixos/core/network.nix
    ../../../modules/nixos/core/user.nix
  ];

  networking.hostName = "my-new-node";
  system.stateVersion = "24.11";
}
```

### Step 3: Register in `flake.nix`
Open `flake.nix` and add the host to `nixosConfigurations` (or `darwinConfigurations`):
```nix
"my-new-node" = mkNixos {
  system = "x86_64-linux"; # or "aarch64-linux"
  modules = [ ./hosts/nixos/my-new-node ];
};
```

### Step 4: Rebuild & Switch
On the target machine:
```bash
rebuild
# or explicitly: sudo nixos-rebuild switch --flake ~/src/infra#my-new-node
```
